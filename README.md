# Универсальный чат для стримеров – Релиз v1.0.0

## Описание

Это локальное приложение, которое объединяет чаты из Twitch и TikTok в один удобный поток, который можно легко интегрировать в OBS, Streamlabs или любое другое ПО для стриминга через браузер-источник.

### Основные возможности
- **Поддержка Twitch и TikTok** – добавляйте любые каналы из этих платформ.
- **Единый интерфейс чата** – все сообщения отображаются в одном окне, упрощая модерацию и взаимодействие с аудиторией.
- **Страница для OBS** – готовый виджет по адресу `http://127.0.0.1:8000/obs/` для мгновенной интеграции.
- **Управление источниками** – добавление, редактирование и удаление каналов прямо в веб-интерфейсе.
- **Полностью локальное** – никаких внешних серверов, регистрации разработчиков или сложной настройки. Все работает на вашем компьютере.

## Как использовать

1. **Скачайте** последнюю версию репозитория.
2. **Запустите** приложение (двойным щелчком по исполняемому файлу.
3. Откроется браузер автоматически по адресу:
   - **http://127.0.0.1:8000/** – панель управления источниками чата.
4. На этой странице:
   - Введите название платформы (Twitch/TikTok) и никнейм канала.
   - Нажмите «Добавить» – канал появится в списке ниже.
   - При необходимости отредактируйте или удалите источники.
5. Для получения ссылки на виджет:
   - Нажмите кнопку «Перейти к виджету для OBS» (или перейдите напрямую по `http://127.0.0.1:8000/obs/`).
   - Скопируйте отображаемый URL.
6. В OBS/Streamlabs/XSplit:
   - Добавьте новый источник → **Браузер**.
   - Вставьте скопированный URL.
   - Установите желаемую ширину и высоту (например, 400x300) и разместите на экране.

## Технические детали (для любопытных)

- Приложение построено на **Django** – надежном веб-фреймворке на Python.
- Модель `ChatTarget` хранит информацию о каждом источнике (платформа, никнейм, статус включения).
- Представления предоставляют CRUD-операции над источниками и отображают виджет.
- Виджет (`obs/obs.html`) использует lightweight JavaScript для подключения к WebSocket-потоку и отображения сообщений в реальном времени.
- Все данные хранятся в локальной SQLite базе данных (файл `db.sqlite3` в корне проекта).

- Закрытие окна браузера не останавливает приложение – оно продолжает работать в трее/фоновых процессах до явного завершения.
